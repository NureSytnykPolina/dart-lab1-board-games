# Лабораторна робота №1

## Варіант 14 — Клуб настільних ігор

### 1. Опис завдання

Розробити консольну програму мовою Dart для обробки інформації про настільні ігри. Програма повинна виконувати розбір і перевірку даних, фільтрацію, перетворення, групування, сортування та формування звітів.

### 2. Структура програми

Основна логіка розміщена у файлі `bin/lab1.dart`.

Обрано функціональну структуру з окремими функціями для розбору, перевірки, групування, сортування та формування звітів. Такий підхід дозволяє розділити відповідальність між частинами програми, спростити перевірку та повторне використання коду.

Основні файли проєкту:
- `bin/lab1.dart` — реалізація програми;
- `test/lab1_test.dart` — автоматизовані тести;
- `pubspec.yaml` — конфігурація проєкту та залежностей;
- `analysis_options.yaml` — налаштування статичного аналізатора;
- `README.md` — документація проєкту.

### 3. Обґрунтування вибору типів даних

Для опису настільної гри використано record `BoardGame`, який містить назву, видавця, кількість гравців, тривалість, складність, рік випуску та дату додавання.

Для результату розбору використано record `ParseResult`, який зберігає або коректну гру, або повідомлення про помилку.

Основні колекції:
- `List` — зберігання вхідних записів та списків ігор;
- `Map` — групування ігор за видавцями;
- `StringBuffer` — ефективне формування текстового звіту.

Records обрано замість класів, оскільки дані мають фіксований набір полів і не потребують окремої поведінки або складної об'єктної моделі.

### 4. Реалізовані функції

У програмі реалізовано:
- розбір даних за допомогою `split()` та `tryParse()`;
- перевірку обов'язкових полів;
- валідацію кількості гравців, тривалості, складності та року випуску;
- конвеєри обробки даних із використанням `where()`, `map()` та `fold()`;
- групування ігор за видавцями;
- обчислення середньої складності для кожного видавця;
- сортування за роком випуску та назвою;
- формування звіту з використанням `StringBuffer`;
- замикання для підрахунку викликів функції;
- маскування назв видавців регулярними виразами;
- обчислення кількості днів від дати додавання за допомогою `DateTime` та `Duration`.

Для сортування використано метод `sort()` із двома критеріями: спочатку рік випуску, потім назва гри. Це забезпечує додаткове впорядкування ігор з однаковим роком.

Конвеєри обрано замість окремих циклів для кожної операції, оскільки вони дозволяють послідовно фільтрувати, перетворювати та агрегувати колекції.

### 5. Залежності pub.dev

У проєкті використовуються такі залежності:

**lints (^6.0.0)**

Використовується для перевірки стилю та якості Dart-коду. Допомагає виявляти потенційні помилки й дотримуватися рекомендованих практик. Альтернативою є використання лише стандартного аналізатора Dart без додаткових правил.

**test (^1.25.6)**

Призначений для створення та запуску автоматизованих тестів. Дає змогу перевіряти правильність роботи окремих функцій. Альтернативою є ручна перевірка результатів виконання програми.

**path**

Не підключається безпосередньо до програми. Залишився у дереві залежностей як транзитивна залежність іншого пакета.

Основна логіка програми використовує стандартну бібліотеку Dart і не потребує сторонніх бібліотек.

### 6. Перевірка програми

Отримання залежностей:

```bash
dart pub get
```

Форматування коду:

```bash
dart format bin/lab1.dart test/lab1_test.dart
```

Статичний аналіз:

```bash
dart analyze
```

Запуск програми:

```bash
dart run
```

Запуск автоматизованих тестів:

```bash
dart test
```
